# 当前实现方案 review

## 结论

当前冻结 plan **通过**，并已按“剃刀定律 + 墨菲定律”落地第一版可运行实现。

## 为什么选这套最小方案

### 剃刀定律

保留最少但必要的部件：

- 一个 API 容器
- 一个 Web 容器
- 一个 SQLite 数据文件
- 一个数据根目录
- 一个可切换的运行适配层（`mock` / `ainovel`）

没有额外引入 Redis、Postgres、消息队列、K8s、对象存储或复杂前端状态框架。

### 墨菲定律

每个容易出问题的点都留了保护：

- **无凭证**：`mock` 引擎先打通整条链路
- **误碰现网**：compose / 目录 / 容器 / 网络全部 `xiaobai` 前缀
- **端口冲突**：仅绑定 `127.0.0.1:3210`
- **凭证泄露**：API Key 服务端加密存储，前端只看脱敏值
- **并发失控**：每操作者 1 个、全站 2 个
- **验收波动**：提供 `pytest` API 烟测 + 本地 compose 一键验证
- **云上风险**：先 IP 验收，再挂域名

## 当前已验证事实

- API 自动创建引导管理员
- 邀请码领取闭环可用
- 模型凭证保存可用
- 作品创建 / 启动 / 完成闭环可用（mock）
- Web 可构建
- Docker Compose 可启动，`http://127.0.0.1:3210/api/health` 可达
